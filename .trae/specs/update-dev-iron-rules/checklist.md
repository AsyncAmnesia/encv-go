# Checklist

## 规则文档完整性

- [ ] 开发铁律规则文档已创建/更新，包含以下内容：
  - [ ] 严禁 mock 大量 handle 的规定和示例
  - [ ] 严禁阻塞式服务启动的规定和后台运行方式
  - [ ] Go 程序使用 `go run` 直接运行的规范
  - [ ] 端口必须正确的标准和端口分配表
  - [ ] Capacitor 前后端预览的标准启动流程

## Mock 代码清理

- [ ] 已审计 mock 目录并列出所有 handle mock
- [ ] 已识别并删除批量的 mock 生成逻辑（>5 个的批量创建）
- [ ] 仅保留 2-3 个核心场景的真实数据 mock
- [ ] 已更新相关引用文件（如 mock/index.ts），无编译错误
- [ ] Mock 总数量 < 10 个（符合最小化原则）

## 端口配置正确性

- [ ] Go 后端 API 默认端口为 **2025**
- [ ] Vite 开发服务器端口为 **5173**
- [ ] Vite proxy 配置正确转发 `/api/*` 到 `http://localhost:2025`
- [ ] 无硬编码端口号散落在业务源码中（应在配置文件/常量中统一定义）
- [ ] 端口冲突时有清晰的错误提示信息

## 服务启动方式验证

- [ ] Go 服务可通过 `go run ./cmd/encv/ serve --port 2025` 启动
- [ ] Vite 可通过 `npx vite --port 5173 --host` 启动
- [ ] 服务支持后台运行模式（& / nohup / tmux / screen）
- [ ] 后台运行的服务有日志输出位置
- [ ] 提供停止服务的方式（kill 进程 / stop 脚本）

## Capacitor 预览流程

- [ ] 文档描述了完整的 3 步启动流程：
  1. 启动后端 Go 服务（后台，端口 2025）
  2. 启动前端 Vite 服务（端口 5173）
  3. 启动 Capacitor 同步/预览（可选）
- [ ] 流程中明确标注了每个命令的工作目录
- [ ] 流程中包含了常见问题排查指引（如端口冲突、代理失败等）

## 代码质量保障

- [ ] 删除 mock 代码后现有测试仍能通过（或已标记为待修复的集成测试）
- [ ] 无未使用的 import 或死代码残留
- [ ] Git 提交信息清晰说明了本次规则更新和代码清理的范围

## 可选增强项（脚本工具）

- [ ] （可选）提供了 `scripts/dev-start.sh` 一键启动脚本
- [ ] （可选）提供了 `scripts/dev-stop.sh` 一键停止脚本
- [ ] （可选）脚本包含端口占用检测功能
- [ ] （可选）脚本有使用说明注释
